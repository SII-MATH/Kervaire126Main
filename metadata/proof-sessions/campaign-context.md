角色本身只规定长期职责；本文件和模块 prompt 提供本次具体要求。

## 工作区、来源与任务边界

- 一个 session 只负责 AdamsSynthetic、Literature、Computation 中的一个模块。只补已有责任；新增辅助声明私有。遵守当前 AGENTS、依赖方向与普通公共导入约束。
- 三个 session 使用不同工作树/分支；已在合适独立工作树则复用，否则优先使用 Codex 原生工作树能力建立 `codex/complete-<module>-<run-id>`。先记录实际基线 SHA、路径和已有脏文件；不切换、重置、stash 或覆盖共享主工作区及他人的进度。
- 只读候选源为 `a484b981fad612eabe2bc7a01b54e049e9a01ce4`；可读 prune 分支作背景，但不能混入后续提交未审查的变化。用 `git show` 或单独只读副本查来源，不 checkout 覆盖当前文件、不整体 cherry-pick。
- 候选文件的目录、命名和公理边界不决定本仓库责任。按当前接口核对量词、前提、宇宙、对象、分次、有限窗口和证明依赖；保留原始来源及当前适配记录。
- 上游已登记待补接口可正常调用，记录传递依赖，不等其他 session 先补完。遇到上游疑点交其责任模块的人审报告，不越权接手源码。
- 已有预谱、Milnor cobar、计算表等实现应复用。不得用空/平凡范畴、自造坐标模型或弱化谓词代替接口指定的真实数学对象；不得引入额外前提、公理、sorry、结果包或循环证明。

## a48 迁移优先级

- 第一阶段以 `a484b981fad612eabe2bc7a01b54e049e9a01ce4` 中可兼容当前固定接口的实现迁移为主任务；先建立源文件/声明到当前接口的粗映射，边盘点边迁移，不等待完整清单才开始推进。
- 每项记录源定位、当前接口、前提/对象差异、状态与下一步。状态区分：已具备、可迁移、需适配、人审阻塞、依赖阻塞、源中仍未证、不适用。已具备的等价实现不重复搬；不能把原来的公理/假设字段计为已迁移证明。
- 证明 worker 优先移植已有构造/证明，完成连接当前接口所必需的私有桥接与适配证明；反例审查、独立核验和接口报告围绕这些迁移目标同步进行。
- 有非阻塞 a48 迁移项时，优先继续这些项，不把 agent 转去无关的从零补证。只有可推进迁移项均已验证迁入、确认已有或确实阻塞/不适用，并给出理由后，才扩展到额外的从零补证。
- 人审只阻塞相关依赖闭包；先继续其他非阻塞 a48 迁移项。主要交付是迁移清单、实际迁入/适配的代码和验证证据，待补数量仅作辅助统计。

## 多 agent 与文件归属

- 每批至少分配多个独立证明研究任务，并安排独立反例猎手、核验者。可用槽位不足时分批复用 agent；保持反例搜索与证明探索并行，不只在证明结束后才审查。
- 一个文件同时只有一个写入者。Literature 和 Computation 的 `Standard.lean` 集中大量待补：多个 worker 可并行找证明、在独占目录做最小实验并提交“目标名、基线文件 SHA、局部补丁、依赖、验证结果”，由唯一写入者串行应用。不能因修改不同声明就并发改同文件。
- 父协调者唯一写本模块 API/contracts/sources 状态和本工作树的全局 `proof-obligations.json`；子 agent 不批量刷新锁、不改共享脚本。向 worker 明确允许编辑的具体文件及证据目录。
- 不同工作树的全局待补清单最终需按模块合并，不用某分支的旧整文件覆盖另一模块进展。没有授权不替其他 session 合并、提交或推送。
- 共享 `REVIEW_ROOT` 仅用于人审报告和证据；每问题独占目录，不共写全局索引。先搜索已有同目标问题，优先补充同一报告的独占新证据；只有报告员修改 report.md。用模块、session/run-id 和随机后缀避免目录重名。

## 反例及接口人审

- 证明困难、来源缺失或未找到反例都不决定接口真伪。反例需核验真实前提、固定对象和约定，区分实际反例、抽象模型反例、有限计算证据、条件性反例和未决疑点。
- 对目标及其依赖链做源码与公理审计。不能通过目标本身、循环结果、相关未证责任或不一致环境推出 False，再把 False.elim 当成证明或反例。依赖其他登记待补的证据如实标为条件性；普通上游调用仍可用于补证，但不宣称得到无未证依赖的最终结果。
- 任何成员认为公共名称、类型、前提、语义、对象关联、导出或责任需要调整，协调者必须另派 `kip_interface_reporter`；报告员与实现/发现者分离，独立核对，不能让发现者写完报告就充当独立审查。
- 报告路径：`REVIEW_ROOT/<责任模块>/<issue-id>/report.md`，必要证据同目录。给人类绝对路径。即使问题跨模块，也要指出原接口的责任方和各模块影响，不直接改对方接口。
- 默认状态 `pending-human-review`，`human_decision: null`；agent 无权自行批准。只有人类明确批准具体报告、方案和范围后才能安排实施；有聊天授权可记录原话及出处，不能伪造人工决定。
- 报告需解释设计背景、问题成因、精确证据、最小修正和保留接口的备选方案、强弱变化、对象关联、调用方/测试/来源/责任的影响。只停真正受该问题影响的目标，继续其余任务。
- 阻塞按数学依赖闭包传播：已出现可信反例的接口及依赖它的任务暂停，不能把该接口当现成上游引理绕过问题；继续真正独立的目标。未核实的猜想只标为疑点，不据此冻结整个模块。
- 正常补证明及其真实状态更新已经获得授权，无需为每个 lemma 再问确认。若类型/导出指纹变化，先核对实际 kernel 类型、宇宙和声明；不可盲目改锁。只有证明状态、实际公理依赖收缩、源码哈希和已完成直接责任的移除，按真实证据同步。
