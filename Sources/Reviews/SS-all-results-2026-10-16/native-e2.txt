# SS 顶层实际 E₂ 求像：独立原生交叉复核

审计日期：2026-10-16。该审计只读官方输入与日志，不更改 Lean 公共接口、程序源码或数据库。

## 结论

- 3,736 条成功 `SynCs` 顶层记录全部完成 E₂ 求像；零像 3,430 条、非零像 306 条，0 条未解。
- 独立 Python 与使用官方原始 C++ 代数库的 evaluator，对每条记录的目标双次数、完整目标 E₂ 基坐标和零／非零分类完全一致：0 差异。
- 根据另行核对的顶层分支控制流，这对应 3,430 次顶层 M0 和 306 次顶层 M1；分类本身无须重建历史 Adams staircase。
- 对全部 306 个非零像，再施加该余纤维三角的下一箭头，306 个结果全部为零。其余 3,430 个零像的复合也当然为零。这个 `g(f(x))=0` 测试独立检验了方向、悬挂、坐标和复合的一致性。

## 独立性的范围

Python 实现以 F₂ 单项式和 Gröbner 消元求像；原生实现直接链接官方源码的 `Deserialize<Poly/Mod>`、`Indices2Poly/Mod`、`subs`、乘法、`Groebner::Reduce`、`GroebnerMod::Reduce` 和 `Poly2Indices/Mod2Indices`。原生方法没有调用 Python 算出的中间式或输出。原生 SQL 通过 `sqlite3_open_v2(..., SQLITE_OPEN_READONLY, ...)` 打开全部文件，basis/images 用 `ORDER BY id`，relations 用官方 `ORDER BY t`。

两者共享已审计的 map 解码表 `input-map-decoding.json`，因此不能把一致性当成该解码表的独立证明。另已对照官方 `ss/loadsave.cpp` 核对：同名 map 按第一个已加载声明解析；factor 读取正确 ring/module 的指定双次数基；composition 按子映射顺序依次作用；file map 的 filtration 和 suspension 取 `ss.json`。完整输入与原subset的 `ss.json` 字节相同。

这次涉及 174 个不同的顶层映射。按顶层 map 存储形式分组：

| 输入映射形式 | 零像 M0 | 非零像 M1 |
|---|---:|---:|
| file | 1518 | 128 |
| factor | 1410 | 155 |
| composition | 502 | 23 |
| 总计 | 3430 | 306 |

具体回归样例：日志 `2413041`，`S0__C2`，源双次数 `(14,100)`、源向量 `[1]`，精确 E₂ 像为目标同次数向量 `[2]`，属非零像／M1；再沿 `C2__S0` 求像为零。完整输入与输出见 `native-E2-test-examples.json`。

## GL 的附加求像

对日志代理给出的 499 个可恢复父提示，各求两次 E₂ 像，共 998 个请求，原生计算全部成功：482 个零像、516 个非零像，0 未解。见 `native-GL-E2-classification.json`。这里的输出字段 `branch=M0/M1` 仅编码零／非零，GL 内真正的 D/M0/M1 必须再结合输出长度、映射 AF 和实际目标同余等信息，不能只靠这个字段认定。499 并非全部历史 GL 成功记录，998 也不是成功 GL 条数。

## 仍未认证的内容

- 没有从末态数据库重建每次调用当时的 staircase、boundary witnesses、crossing cutoffs 或递归调用树。
- M1 只证明顶层 E₂ 像非零；其边界表示和递归前像选取的历史值仍未恢复。
- 不证明官方 E₂ 数据与真实谱序列的数学对应，不证明 map 数据或全部 Gröbner relations 的来源正确。
- 不由求像分类推出 MH2、GL 的修正版已经成立；还须逐分支比较实际 mathematical hypotheses。
- 不把 17 个 Lean Main 根的无 sorry 审计推广为 SS 所有计算结果的认证。
- 原生 evaluator 对当前 3,736 + 998 请求全部支持，但不是所有可能 SS map 类型的通用实现；非恒等 scalar-over file map 会明确抛出 unsupported。

## 复现

在 `/tmp/SS-All-Results-Audit-20261016` 下，官方源码完整展开在 `native/SSeqCpp-master`。

```bash
cmake -S native/SSeqCpp-master -B native/build -DCMAKE_BUILD_TYPE=Release
cmake --build native/build --target algebras -j 4
c++ -std=c++20 -O2 \
  -Inative/SSeqCpp-master/include \
  -Inative/SSeqCpp-master/thirdparty/nlohmann_json \
  -Inative/SSeqCpp-master/thirdparty/fmt/include \
  native_e2.cpp native/build/src/libalgebras.a \
  native/build/thirdparty/sqlite3/libsqlite3.a \
  native/build/thirdparty/fmt/libfmt.a -ldl -lpthread -o native_e2
./native_e2
./native_e2 logs-gl-E2-requests.json native-GL-E2-classification.json
./native_e2 native-E2-cofiber-composition-requests.json native-E2-cofiber-composition.json
```
