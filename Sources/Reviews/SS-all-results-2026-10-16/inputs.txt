## 3. M0 静态参数精确解码

加载器 `loadsave.cpp:275–296` 对 factor `[stem,s,index]` 取 AF=s、内次数 t=stem+s；`:299–362` 对 composition 取各条箭头 AF 与 t 位移之和；`:367–371` 对文件映射取 `fil`（缺省 0），t 位移为 fil−sus。这只解码程序标签，不独立证明拓扑映射真有该 Adams filtration、或其所选 E2 代表正确。

每个配置三角 `(i,q,d)` 恰好只有一条箭头 AF>0，其余 AF=0。若这些确为所声称的拓扑余纤维三角，则长正合列给出正 AF 箭头 e=1，其余 e=0。61 个 AF 三元组：56 个 `(0,0,1)`、4 个 `(0,0,2)`、1 个 `(0,1,0)`（`Fphi → RP1_256 → S0`）。

对算法当前箭头 f（rotation=iTri），令 g=next、h=prev，直接找前像 M0 的 h、g 输入长度为 `l₁=AF(h)−e(h)`、`m₁=AF(g)−e(g)`。8 个非零方向为以下四个三角的 rotation 0、1：

| 三角 | rotation 0 `(l₁,m₁)` | rotation 1 `(l₁,m₁)` | rotation 2 |
|---|---|---|---|
| S0 → C2sigma → S0 | (1,0) | (0,1) | (0,0) |
| S0 → Csigmasq → S0 | (1,0) | (0,1) | (0,0) |
| S0 → Ctheta4 → S0 | (1,0) | (0,1) | (0,0) |
| S0 → Ctheta5 → S0 | (1,0) | (0,1) | (0,0) |

这不是“仅四个非零调用”，也不表示成功日志只来自这些方向；57 个零输入层三角可在递归中产生正的数学 level。配置不给出微分长度 r、源双次数、实际数学 λ-level、非零目标性或 crossing 的成功数据；必须对照具体状态和成功调用。

## 4. M0 / M1 和递归的输入区别

`category.cpp:541–710`：

- M0：f 的 E2 像为空；`:598–622` 沿 h 的整个 staircase 基求指定前像，再读其微分。检查已知微分和源 level 不等式，随后沿 g 在模边界的商中求目标。
- M1：E2 像非零但被已知微分击中；`:559–595` 从该边界的前像经 g 取 xtop，再递归调用上一方向 `GetSynImage(iCof.prev(),...)`。递归输出与 x 仅要求在 `level_x` 所定基子空间中同余（`:590–594`），不是指定 synthetic 代表元逐字相等。
- 两者共享目标 kernel / image 检验（`:637–671`）、cutoff 以上的递归 crossing 搜索（`:673–705`）。crossing 搜索同样会递归调用 GetSynImage，且 depth_ 不随这种递归增加。
- `level_x` 是 staircase 编码。`main.h:20–23` 定义 LEVEL_MAX=10000、R_PERM=1000、LEVEL_PERM=9000；`ss.cpp:214–242` 对向量消元后返回所在层的已知/未知微分状态。它不是王稿的 λ-level。

因此待证明的程序契约必须按“任意合法输入状态 + 指定向量 + 三角方向 + cutoff + 目标同余精度”归纳，而不能仅写成某个球面双次数的零层 MH2。M1 还需要递归商兼容、同余替换的可消费性、足够长商中的实际代表、边界与 cycle 的 level 调整，以及两种递归（恢复前像、排除 crossing）的良基性/正确性。输入配置本身不提供这些桥梁。

## 6. 当前配置不等于归档所有计算数据

官方 database 归档目录包含 362 个 DB：当前 ss.json 只引用 290 个（49 个谱 + 180 个文件映射 + 61 个余纤维 SS），另有 72 个 DB（13 个谱、59 个映射）未在当前配置出现。包括 `Ceta_Cnu`、`Cnu_Csigma`、`C2_Ceta_Cnu`、`CW_eta_V_nu`、`CW_nu_V_sigma`、`CW_eta_A_nu`、`CW_nu_A_sigma`、`CW_sigmasq_2_sigmasq`、RP5/7/9/11/13_256。

这有两个不同含义：当前运行加载器不会自动读入这些多余文件；但若要求认证“所有归档计算结果”，必须包含它们，或明确证明它们不属于所声称输出范围。历史 proofs.db 是否有配置外对象由日志代理另行比对。当前归档目录没有 log.db/checkpoints；proofs.db 单独提供最终输出级证明日志，不能自动补齐所有运行时内部输入。全量数据库完整性和 SHA256 清单由 root 的 `full-inputs-verified.json` 给出。

## 7. 对王稿覆盖范围的输入侧判定

王稿保留输出 level 的 basic MH2（两辅助输入为零层）有望覆盖 M0 的一般参数族，前提是提供真实三角/映射标定、微分与 cycle 资格、正确的 crossing 商及级数边界；它不是只支持 `(0,0)`，四个正层三角也不应仅因 l₁/m₁>0 就宣布反例。是否得到机器实际写入的经典非零目标，还必须有较长商关系的解码条件。

M1 的递归输入通常已经是 hidden extension，且程序只保留 quotient residue 的一致性；basic MH2 的零层输入没有直接覆盖它。common-level 版本若仍缺源 cycle/可见范围/长商提升前提，也不能由“配置只有57个AF1三角”消除问题。具体缺失条件由 MH2 与 GL 数学代理给出；本输入审计没有宣布任何机器输出错误，也没有认证全部输出安全。

## 9. 新增：全量 E2 运算实证区分顶层 M0/M1

已从完整官方数据库独立实现 E2 代数求像器 `/tmp/SS-All-Results-Audit-20261016/evaluate_e2.py`。对每条 SynCs 的实际 f、源度数及 E2 基向量，在 GF2 上读取文件生成元像、factor 和 composition，并以导出的 ring/module Groebner 基化简，得出 f_E2(x)。程序全部只读打开 DB。3736 条全部算通，源坐标合法，化简结果均能精确回到目标 E2 基：

| 顶层实际分支 | 已记录成功输出数 | 判断依据 |
|---|---:|---|
| M0 | 3430 | f_E2(x)=0，进入源码 category.cpp:598 直接求前像 |
| M1 | 306 | f_E2(x)≠0；SynCs调用者跳过输出长度等于AF的直接像，只能进入 category.cpp:559–595 的边界像递归 |

M0 中 3,429 个为 `(l₁,m₁)=(0,0)`，只有 1 个为 `(0,1)`；真实顶层微分长度 r=2/3/4/5 的数量分别为 2,876/473/65/16。唯一正 m₁ 的 M0 是日志 `2414551`：`C2sigma__S0`，源 `(s,t)=(40,135),x=[2]`，输出长度 1、目标 `[1]`；顶层输入 d₃，h 为 `S0__C2sigma`，g 为 `2σ`。因此全部实际顶层 M0 都有 **l₁=0**，输出数学 level 在 basic MH2 中无需正层遗忘；仍需逐项证明前提。

M1 中 295 个方向的静态 M0 参数为 `(0,0)`，11 个为 `(1,0)`，但其递归实际参数必须重建，不能用静态 M0 参数代替。因此旧静态清单中 12 条“正方向”输出的 11 条实际都是 M1。

第一轮结果 `E2-branch-classification.json`，可重放 `python /tmp/SS-All-Results-Audit-20261016/evaluate_e2.py`。独立代理已用官方原生 C++ `Deserialize / Indices2Poly / Indices2Mod / subs / Groebner::Reduce / Poly2Indices / Mod2Indices` 完整重算全部 3,736 个实际 E2 像。逐行目标双次数、完整 E2 像坐标与分支全部一致，零差异；见 `native-E2-classification.json`、`native-E2-crosscheck.json` 与 `native_e2.cpp`。这比只抽样检查中间式更强。

这一新证据消除了“递归分支是否真的成功使用”的不确定性：**306 条输出确实经过顶层 M1，因此支撑全部机器输出的定理族必须覆盖递归 hidden-extension 输入。** 然而 M0 内部仍有 crossing 检查递归，M1 恢复前像递归也可更深；本分类不声称已恢复每层有限商或 λ-level。
