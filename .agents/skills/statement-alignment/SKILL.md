# 陈述对齐检查

按当前任务确定声明和来源范围。普通内部辅助引理可直接比较，不要求每次编辑启动整套审查。先读仓库根目录 [AGENTS.md](../../../AGENTS.md)，它规定当前模块、接口与记录规则。下文路径均以仓库根目录为基准。

## 固定两侧输入

- 原文：论文版本、编号、段落及周围定义和约定。AimPaper 原始陈述在 `AimPaper/main.tex`；当前形式化目标在 Blueprint 数学条目中。先查 `corrections.yaml` 和相关提案的明确授权，区分“忠实原文”和“符合已批准修正版”。不能用当前较弱的 Blueprint 自行证明其偏离原文合理。
- Lean：提交及相关未提交改动、实际定义源文件、全限定名、完整声明和解释它所需的定义体。责任模块按源文件与 `interface/baselines/*-api.json` 确定，不能只按命名空间猜测。
- 用当前工具链的 `#check`、`#print` 或可用的语言服务查看 elaboration 后的类型，显式检查 universe、section 参数和类型类实例。未执行时标明“仅源码阅读”；网页源码展示与接口锁中的类型指纹都不能替代完整类型。

## 回译与比较

先根据 Lean 类型及定义，写出独立可读的数学命题，再与来源逐项比较。不要按声明名称或注释补入类型没有的条件。关键定义的数学含义属于本检查范围；仅为表示便利性、API 复用等问题，才进一步使用 [definition-quality](../definition-quality/SKILL.md)。

比较对象和定义域、量词顺序与见证依赖、全部前提、结论强弱、边界与正则性、分次及映射方向。追踪模型、商对象、所选同构与标准类的实际定义；代理表示需要到原对象的对应及正确方向的桥接。具体检查方法见 [语义探针](references/semantic-probes.md)。

重要目标需要降低确认偏差时，可在同一会话分开做回译和比较，但不能称为独立审查。任务已明确要求独立复核、且具备相应执行条件时，回译者只接收完整声明和必要定义，不接收预期原文或既有裁决；比较者再接收原文与回译。不要仅为本 skill 启动额外编排流程。

## 用证据区分差异

- 小型区分实例必须满足声明的全部前提，并作用于声明实际固定的对象。一般抽象模型的反例只能反驳相应泛化，不能直接反驳 `Standard.model` 上的目标。
- 将“未找到桥接”“桥接已登记但待证明”“已证明不匹配”分开。上游已登记的构造或证明责任可以按项目规则直接调用，不把责任移给下游，不额外要求调用者提供结果包。
- `sorry`、传递待补依赖与对齐结论分别说明。陈述可对齐而证明未完成；编译通过或只使用标准公理也不保证陈述对齐。未找到反例不能证明等价。
- Lean 探针放在许可的临时目录，使用固定工具链和依赖；记录源文件、实际命令及结果。不得为完成检查修改公开声明、接口锁、依赖或许可证明洞。

## 结论与项目记录

按证据报告：未发现差异（限定已查范围）、已确认差异（精确差异及区分证据）、或尚无法确认（缺少定义、来源或未闭合桥接等）。缺少桥接证明本身不证明两种表示不等价。列出原文定位、实际声明及关键定义、回译、差异影响、实际验证和未查范围。仅源码阅读不得写成已编译验证。

一般检查直接在回复中给结果。需要持久化接口问题时，更新已有对应提案，或按 [接口提案指南](../../../docs/interface-proposals.md) 写入 `interface/proposals/<责任模块>/<唯一ID>/report.md`。没有独立复核时如实用研究草稿，不能填写虚假的独立性或批准状态。相对 AimPaper 的修正仅维护于 `corrections.yaml`，正文与修正版引用原文和 Blueprint，不另建平行契约、来源表或修正记录。

安装或调用本 skill 不授权接口修改。已有授权按其范围执行，不重复请求；需改变冻结接口时，先给出精确差异、理由及下游影响。只标记确实受影响的目标，其余保接口工作可继续。Blueprint 绑定遵守同模块、公开锁和正文实际结论的规则，不把辅助步骤绑定成主结论。

复用未变输入的检查证据；纯证明体改动只有在影响关键定义、实例或声明含义时才需重做对齐。实际修改后的验证按 `AGENTS.md` 执行；本 skill 不新增逐声明审查门禁或网页发布前全量编译要求。
