# 表示实验

只调查已定位的使用问题。原公开接口保持不变，候选放在许可的临时区域。

## 比较对象和接口

区分定义相等、命题相等、同构/等价以及显式 transport。别名可保留定义相等；新类型能区分同载体上的不同结构。没有通用的优劣排序。

候选映射表示优先与锁定库已有的 hom、线性映射、连续映射、等价等比较，查看复合、恒等、强制转换和外延性接口是否适用。现有抽象过强时，指出具体多要求的字段或前提，而不是另造一套近似相同的结构。

性质与携带所选数据的结构并不相同。把存在性改成所选数据可能引入选择和运输成本；把数据改成存在命题可能让每个消费者反复取见证。用实际构造者和消费者比较两种成本。

## 核对实际实例

相同载体上的不同代数、拓扑或范畴结构，可能让表面相同的类型含义不同。查看 `#print`、显式参数 `@declaration` 或可用语言服务，确认每个表达式使用的实例。

新引入的局部实例会影响后续 elaboration，不会改写之前已生成的项。固定签名内需要原环境实例时，先捕获并显式传递该实例；仅给竞争结构起名不一定解决冲突。

先比较局部实例及作用域，不能为一个证明便利就导出全局实例。测量合成循环、diamond 或开销时保留最小复现，不能仅凭存在多条实例路径判错。

## 用消费者决定修复范围

选择能暴露问题的构造、操作、简化或下游定理；不要求每次凑齐全部实验。比较旧/新表示的显式转换、所需假设和实际诊断。涉及公共 API 时以普通公共导入验证，不用跨模块 `import all`。

若补一个桥接引理即可消除重复转换，优先评估该方案。整体替换定义前搜索所有构造者、实例、消费者、公共导出、测试和 Blueprint 绑定，说明迁移范围；涉及冻结接口时先按已有授权边界处理。

性能实验保持工具链、依赖和缓存状态可比，不能并发共写同一缓存。记录检查了什么、是否真的运行、结果及局限。候选未完成时报告不确定性，不称其为已验证替代。
