# 定义质量审查

先读仓库根目录 [AGENTS.md](../../../AGENTS.md)，按任务确定定义、消费者及责任模块。下文路径均以仓库根目录为基准。默认交付审查意见；实际编辑沿用用户授权，不把发现改进当作重构授权。

## 从真实用法出发

读数学来源、定义体、构造者、投影、相关实例，以及至少一个真实下游用法。责任归属按实际源文件和模块接口锁判断，旧命名空间并不决定当前模块。搜索调用方时包括普通公共导入的 `Tests/<模块>/` 消费者。

如果只有“定义是否忠实原文”的问题，用 [statement-alignment](../statement-alignment/SKILL.md) 的语义检查即可。需要评价表示方式时，再检查下面适用的方面：

| 问题 | 需要的证据 |
| --- | --- |
| 表示正确吗？ | 原文对象、定义体、实际构造及到规范对象的桥接 |
| 是否重复已有 API？ | 项目与锁定 mathlib 中候选的完整类型、所需前提及真实使用方式 |
| 封装有帮助吗？ | 构造者和消费者确实一起使用这些数据，或反复重建相同上下文 |
| 使用是否顺畅？ | `exact`、`rw`、`simp` 所需的转换、transport 或额外引理 |
| 实例一致吗？ | 实际选中实例、作用域、diamond、失败或搜索开销的复现 |
| 前提诚实吗？ | 字段是否将目标当输入，或存在从原始假设产生字段的已证明/已登记责任 |

本地源码和当前锁定依赖是 API 可用性的依据；用 `rg`、可用语言服务和小型 Lean 检查即可，无需安装 Horizon 的搜索或重构 skill。别的版本中有同名定理不能证明当前环境可用。

## 区分数学问题与工程问题

语义错误、缺少桥接引理、可约性问题、实例冲突和 API 不便需要不同修复。`abbrev`、结构体、非计算定义、所选同构或重复假设本身不是缺陷。一处证明困难也不足以判定表示错误。

项目中的固定模型可能具有未存成字段、需要另证的性质。不能只因抽象结构缺少一个字段，就判定固定对象上的定理漏前提。上游已登记待构造或待证明的接口可按规则直接调用；如实保留其未完成状态，不转移给下游，也不恢复 Challenge、结果包或额外假设。

工程建议需展示实际收益：减少重复转换、复用已有操作、消除实例冲突，或扩大一个真实消费者可用的范围。不要为假想用户搭建新层级，也不要求所有定义都改成最一般版本。性能判断要有同工具链、同缓存条件下的比较；没有测量就不声称变快。

## 先做最小实验

按 [表示实验](references/representation-experiments.md) 比较候选。尽量用一个有代表性的构造或消费者验证最小替代，保留原公开接口。一个桥接引理足够时，优先比较它与整体迁移的成本。未实际完成或编译实验时，明确建议尚未验证。

公开消费者使用普通 `import KIP126.<模块>`；`import all` 仅限同模块内部及测试审计汇总，不能以它掩盖公共接口不可用。探针放在许可的临时目录，保持固定工具链与依赖，不覆盖共享缓存或他人构建。

## 报告与实施边界

报告定义与消费者、搜索到的替代、问题机制、最小实验及实际结果、预期收益、迁移成本和剩余不确定性。将数学不匹配、实际使用缺陷、可选工程改进分开；编译通过不消除数学问题，风格偏好也不自动成为阻塞项。

一般审查在回复中交付。涉及需要持久化的接口问题，沿用 [接口提案指南](../../../docs/interface-proposals.md)，更新原提案或写入责任模块提案目录，如实标记独立性、证据与已有授权。纯工程建议不需要一律升级成人审提案。论文修正只维护在 `corrections.yaml`，自然语言数学内容与来源仍在 Blueprint，不另建平行记录。

不采用上游“后处理发现低成本改进就必须修复”的规则。这里公共名称、类型、前提、语义、对象关联和导出均受项目接口冻结约束；本 skill 不授权改动它们、接口锁或其他模块。需改变时给出精确方案和受影响消费者，按现有授权执行或提交待审提案；不让整个项目为一个可选改进停工。

获准实施时，保留默认私有、显式 `public`、模块依赖方向及上游责任边界。按 `AGENTS.md` 同步必要消费者与检查，运行 `python3 scripts/check-source-inventory.py` 和 `lake build`；不添加公理、证明洞或放宽检查来迁就表示。网页状态和本地消费者通过均不代替传递信任审计。

来源与本地适配见 [来源说明](references/sources.md)。
